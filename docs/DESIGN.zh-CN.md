# ThetaMill 设计文档

> 低频期权卖方工具箱，只做三种策略：**covered call / sell call / cash-secured put**。
> 目标不是抓行情，而是把 theta（时间价值）按周慢慢收进来。

---

## 一、定位

| 项 | 决定 |
|---|---|
| 语言 | Python 3.10+ / `ib_async` |
| 交互 | 命令行，一条命令一个动作，无后台服务、无 GUI |
| 使用目标 | 人工低频运行；目前没有每日运行/提交次数上限。`plan` 默认 DTE 窗口 21–45 天 |
| 策略 | 仅三种卖方策略，其余一概不做 |
| 执行 | 默认只出建议与复核码，**必须人工确认后才发单** |

### 这个名字在说什么

Theta 是期权 Greeks 里「每天因时间流逝而自动损耗的价值」。卖方赚的就是这一项——持股卖 Call、持币卖 Put，来源都是 theta。

Mill 是磨坊：不靠一次性爆发，靠每天重复同一个动作、慢慢累积产量。磨得慢，但一直在磨。

名字里藏着两条约束：**磨得慢**（低频、不追涨杀跌）、**磨坊会磨损磨盘**（卖方尾部风险真实存在，一次暴跌能抵掉几个月权利金，所以覆盖校验和仓位上限不是装饰）。

## 二、为什么不只用 ThetaGang / ibkrbot / LEAN

| 项目 | 语言 / 许可 | 它解决什么 | 为什么不直接用 |
|---|---|---|---|
| **ThetaGang** | Python / AGPL-3.0 | 完整 Wheel：卖 Put 建仓、被行权后卖 Call、滚动、regime 再平衡、VIX 对冲、现金扫 SGOV | AGPL 有传染性；功能比需要的多出一个数量级；默认依赖 IBC 自动登录。**只借鉴规则**（delta 选价、成本价以上卖 Call、滚动逻辑），代码自己写 |
| **ibkrbot** | Python / MIT | Webhook 收信号 → 编译 OrderGroup → 下单 | 只是执行器，**没有策略**。本项目的执行层已覆盖同等能力 |
| **LEAN + IBKR** | C# / Apache-2.0 | 完整回测 + 实盘框架 | 配置重；本地 CLI 使用 IBKR 功能需付费组织资格；期权卖方策略仍要自己写 |

结论：三个项目里只有 ThetaGang 是策略程序，而它比本项目需要的多十倍。**缺的从来不是执行，而是三种卖方策略的低频调度与准入判断。**

## 三、为什么是 Python

这个项目的风险不在语言，在 **IBKR 协议细节**。以下每一条都是实际踩过并写进代码注释的：

| 现象 | 真实原因 |
|---|---|
| 行情全空，报 `10197` | 同一账户有多个真实交易会话（手机 App 与网关同时在线抢行情通道） |
| 报 `162` 会话来自不同 IP | 与上一条同源：手机走运营商、网关走家宽 |
| 报 `10168` | 延迟行情未启用，且在 IB Gateway 上无按钮可点（需 TWS 图形界面） |
| 美股 `10167` / 港股 `354` | 该市场未订阅，只能拿延迟数据 |
| 订单「看似丢了其实进了系统」 | 网关在提交瞬间断线，`orderId` 已分配但客户端没收到回执 |
| 港股合约取不到、价格算成 1 元 | 港币标的在 `SMART` 下会解析到别的市场，必须走 `SEHK` |
| 期权链行权价全错 | `reqSecDefOptParams` 的 strikes 是**所有到期日的并集**，单月只含子集 |

Python 侧这些坑已经逐个踩完并固化成代码；换语言等于把这份经验清零。

Go 的优势（单二进制、静态链接、并发模型）在本项目场景里价值有限：一天只跑一两次，无长驻服务。

### 什么时候才该改判 Go

出现以下任一情况，且是**外壳**而非重写核心：

1. 要分发到装不了 Python 的客户现场（只给一个二进制）；
2. 要做 7×24 多账户常驻服务 + Web 控制台；
3. 要与现有的 Go 服务共用进程与指标。

## 四、策略目标与当前实现边界

|  | covered-call | sell-call | cash-put |
|---|---|---|---|
| 执行担保 | 净可用股数不足时差额买股，成交后才继续期权腿 | 扣除已占用后的净可用股数 ≥ N×乘数 | 实际现金 ≥ 行权价×乘数×N，并核算存量/在途义务；不把国债或融资购买力当现金 |
| 期权腿 | SELL Call × N | SELL Call × N | SELL Put × N |
| `plan` 选价 | `plan` 不自动建议 covered-call | 目标 OTM 且使用成本价下限 | 目标 OTM；启用白名单时受 `max_entry` 限制 |
| `plan` 到期窗口 | 不适用 | 默认 21–45 天，目标 30 天 | 同左 |
| 权利金 | 人工定价 | `plan` 展示参考权利金与年化，未实现最低年化准入阈值 | 同左 |
| 退出目标（未自动实现） | 人工复核到期、平仓或被行权 | 同左 | 同左；未实现权利金回撤 70% 自动平仓 |
| 拒绝/筛选边界 | 已有足够净可用股数时改用 sell-call | 执行端校验覆盖；成本价下限是 `plan` 选价规则 | 执行端校验现金；接货价上限仅在携带有效白名单时生效 |

`order` 与 `strat` 可人工指定合约，不应把 `plan` 的 DTE/OTM/成本价筛选视为所有执行入口的强制门禁。`strat` 是主命令，`combo` 只是相同实现的兼容别名；covered-call 两腿顺序执行，不是原子组合。确认 multiplier 不等于确认完整交割物，含现金、篮子或未知交割结构的调整合约不自动支持。

**明确不做**：裸卖 Call（风险无限）、价差、跨式、铁鹰、蝶式。这些不是"暂未实现"，是刻意排除——策略越少，出错面越小。

## 五、安全闸

三道闸串联，缺一个都发不出去：

| 闸 | 机制 | 作用 |
|---|---|---|
| 1 | `config.json → live_enabled` 总开关 | 关闭时任何实盘委托在连网关之前就被拒绝 |
| 2 | `--live-ok` 显式参数 | 总开关打开后，漏了这个参数照样拒绝 |
| 3 | 复核码 | 同一条命令必须复跑一次才发单；码里带账户环境，纸账户的码在实盘无效 |

另有两层：

4. **覆盖校验**：无股不卖 Call、现金不足不卖 Put、已有足够股不再重复买。
5. **审计**：只要一笔委托可能已经发出（腿状态为 attempting/submitting/submitted/unknown），`thetamill/submission_cli.py` 就在 `execute_prepared` 返回前尽力写入一条 `orders.jsonl`（`thetamill/audit.py`），记录账户、环境、intent、各腿状态与可获得的 `orderId`/`permId`；预检、迁移冻结与发单前拒绝不写，因此日志里出现券商单号即意味着确实联系过券商。字段严格按类型净化：非 JSON 安全的对象（泄漏进来的 `MagicMock`、ib_async 对象）逐字段丢弃并记入 `dropped_fields`，绝不用 `default=str` 把 mock 的 repr 写成看似真实的一行。写入失败或进程崩溃仍可能留下缺口，因此它不是权威配额账本——`audit` 会同时并入 SQLite 账本（`source=ledger`，状态取 `confirm_leg` 记录的券商正向状态），账本里存在而日志缺失的单会被明确标注。

查询类命令不主动提交委托；其中需要连接券商的命令使用 `ib_async` 的 `readonly=True` 参数。该参数不是服务端订单 ACL，服务端 Read-Only API 配置须单独核实。`audit` 以只读方式同时读取本地日志与提交账本，并隐藏任何带 mock repr 的合成记录（旧版 `default=str` 写入器会留下这类行），只显示可核对为真实委托的条目。

当前 B 阶段已落地：权威 SQLite 提交账本 `thetamill/state.py` 用 `BEGIN IMMEDIATE` 事务完成 intent 认领、资源预留与状态迁移，`thetamill/execution.py` 在发单前刷新券商状态、校验有效期/配额/合约身份后预留，发单前持久化 `submitting` 与稳定 `orderRef`，回执不明进入 `unknown` 并由 `reconcile` 只读对账。账户/环境范围贯穿账本键。

仍需注意的边界：该账本只协调同一主机、同一账本的本工具进程，不控制人工 TWS、其他机器或第三方客户端，也不提供券商 exactly-once 语义；`readonly=True` 是 `ib_async` 客户端参数，不是服务端订单 ACL。旧 JSON 复核码消费记录仅作兼容保留，不再承担并发配额职责。

## 六、命令

| 命令 | 用途 | 写权限 |
|---|---|---|
| `status` | 探测本机哪条网关通了 | 只读 |
| `account` | 账户资金、保证金、缓冲 | 只读 |
| `positions` | 持仓与浮盈 | 只读 |
| `orders` | 未成交挂单 | 只读 |
| `quote` | 正股报价 | 只读 |
| `chain` | 期权链、报价、Greeks、DTE | 只读 |
| `plan` | 当日建议（DTE 窗口 + OTM 选价 + 成本价下限） | 只读 |
| `audit` | 审计日志 | 只读 |
| `report` | 盘中风险快照（终端 / JSON / Markdown） | 只读 |
| `reconcile` | 只读券商对账；不重发、不撤单、不自动解除未知预留 | 只读 |
| `roll-plan` | 展期建议；输出独立 schema，`run` 拒绝执行 | 只读 |
| `order` | 股票/期权单腿下单 | 需复核码 |
| `strat`（别名 `combo`） | 三种策略，备兑两腿顺序执行 | 需复核码 |
| `run` | 执行 `plan` 生成的建议 | 需复核码 |
| `cancel` | 撤单 | — |

典型闭环：

```bash
thetamill --paper plan 700 --currency HKD --json plan.json   # 出建议，只读
thetamill --paper run --file plan.json --i 1                 # 出复核码，不发单
thetamill --paper run --file plan.json --i 1 --code <CODE>   # 真正发出
thetamill --paper audit --today                              # 核对留痕
```

## 八、数据与验证边界

| 约束 | 影响 | 现实对策 |
|---|---|---|
| 未订阅行情 | 美股报 `10167`、港股报 `354`，期权可能无 Greeks；纸账户与实盘共享同一套行情许可 | 报价/FX 缺失会影响计划或风控；查询成功不代表报价有效 |
| 每日强制 2FA | **无法无人值守**：网关一天一断，需人工确认 | 每交易日人工登录一次网关，跑完即退 |
| 历史纸账户测试未成交 | 休市委托仅观察到 PreSubmitted 与撤单 | 成交需交易时段与权限另验；OPRA 针对美股期权，其他市场许可分别核实 |
| 周度/月度期权阶梯不一致 | 某个行权价只在部分到期日存在 | 已实现邻近行权价试探（`_resolve_option`） |
| IBKR `-1` 表示无行情 | 易被误当作有效价格 | 取价时显式排除 ≤ 0 的值 |

## 九、风险声明

本项目是**执行工具**，不含任何投资建议。卖方策略的亏损可以超过收到的权利金，裸卖更是无限风险。所有委托默认需要人工确认，请先在小额纸账户跑通再考虑实盘。使用风险自负。
