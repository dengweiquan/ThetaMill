# 本地状态、风险配置与恢复

本文区分已存在的 A 安全门禁和正在接入的 B–E 功能。以对应发布提交的命令帮助和验收记录为准；不能把开发分支代码视作券商验收通过。

## 账户选择

`--account` 可放在子命令之前或之后；配置 `account` 是默认选择。单账户会话可以自动选择，多账户必须显式选择，禁止跨账户相加担保。账户选择还必须与已连接的 paper/live 环境一致。端口名字不是账户身份的替代证据。

## 风险配置

`config.example.json` 默认 `risk.enabled=false`，没有推荐交易金额或每日单数。关闭 P3 限额不关闭合约身份、真实乘数、Call 股数覆盖和 Put 现金担保等基础执行门禁。

启用前由使用者明确填写：

- `day_timezone`：IANA 时区，如 `Asia/Hong_Kong`。统计该时区自然日，不宣称是所有市场的交易日。
- `max_daily_submissions`：正整数，本工具实际新订单发送尝试次数。备兑股腿和期权腿分别计数，预先预留两笔预算；查询、预检、撤单不计新增委托。
- `per_underlying.amount` / `portfolio.amount`：账户基础币种金额；`null` 表示未配置该可选上限。
- `per_underlying.ratio` / `portfolio.ratio`：净清算值比例；启用时需要可靠净值和估值。
- `max_snapshot_age_seconds`：允许的账户快照年龄。快照新不代表行情与汇率也必然新，数据来源和质量仍须检查。执行用新增估值/FX 证据要求实际时区时间戳、来源以及实时双边报价；历史日线收盘、延迟/冻结行情不能被重新标注为当前价格。取不到必要证据时阻断相关执行，不用旧价或零值补足。

金额与比例同时配置时都要满足。配置变更应使旧复核失效，不提供 force 绕过。首次启用若无法确认当天历史提交计数，不能把空账本当作零发单额度；采用保守迁移或等下一配置日。

风险指标分开看：

1. 交割义务：Call 所需正股、Put 行权价 × 每张真实乘数 × 张数。
2. 潜在持有名义敞口：已有正股估值、在途买股限价金额、存量/在途 Put 接货金额。不是 VaR、保证金或最大亏损；备兑 Call 不重复加算已有股票。

## 只读风险快照

`thetamill --paper report --format json` 输出本地 JSON；`--format markdown --output <新文件>` 创建本地文件。默认账户脱敏，`--reveal-account` 是显式选择。导出拒绝覆盖已有路径，请使用新文件名。

缺行情、FX、净值、账本或券商数据时，报告标记不完整，未知不等于零。股票估值和外币汇率必须与对应来源记录一致；账户快照、估值或汇率过期/未来超出时钟容差时，仍展示原始值与来源，但将共享风险预算置为 `null`，不声称可用。账户快照默认新鲜度窗口为 30 秒，启用相应配置后采用已验证的 `max_snapshot_age_seconds`；行情与汇率仍独立要求 30 秒内，不随账户快照窗口放宽。报告是运行时风险快照，不是正式收盘报表；不从不完整订单日志推算策略已实现收益。首版不向任何外部服务推送。

## 普通计划与执行边界

普通计划条目的 `allowed` 字段若存在，必须是 JSON 布尔值 `true` 才能交给 `run`；预算或证据未通过的条目不能执行。条目编号 `i` 必须是唯一正整数，布尔、小数、字符串编号或重复编号均拒绝，避免选中与 `--i` 不同的条目。

计划数量、行权价、权利金和合约乘数可使用十进制字符串。当前 CLI 与券商对象之间仍存在浮点边界；无法无损传递的数值将明确拒绝，不能静默舍入或自动改量。有效期按真实时间点比较，支持带 UTC 偏移的 ISO 时间；旧无时区计划按执行机器本地时区解释，无法可靠跨时区迁移，应重新生成带时区的新计划。

`allowed=true` 仅表示生成计划时的评估，不是提交授权，也不保证执行时仍有预算。执行前仍须重新核对完整合约身份、真实乘数、账户、行情证据、累计义务和本地预留。当前版本所有公共执行入口（`cmd_order`、`cmd_combo`、`cmd_run`）已完整接入公共执行协议 `submission_cli.execute_prepared`，旧 `_code` 回退与直接 `ib.placeOrder` 完全移除；正向 handoff 严格核验 11 项规范合约身份字段；全新账本净减风险例外保留迁移冻结门禁。

## 提交账本恢复原则

权威本地 SQLite 账本与兼容 JSONL 审计的职责不同：JSONL 写入成功不证明成交，写入失败也不证明没有发单。账本必须在网络发送之前保存 intent、资源预留和稳定 orderRef。

- 回执不明先对账，不重发，不删除消费记录。
- 当前挂单里没找到，可能代表已成交、已取消或历史不可见；不是未发送证明。
- 未知订单占用跨自然日继续保留。跨日只切换每日配额，不清理资金和股数义务。
- 券商拒绝、取消、部分成交不能返还已经发生的提交尝试次数。
- 账本损坏或不可写时拒绝新增风险，不以新建空库、改目录、删锁文件来恢复交易能力。
- 备份需覆盖数据库及其伴随文件，停止所有使用该账本的进程后再进行一致性备份；不要在运行中仅复制一个 SQLite 主文件。
- 不以恢复旧数据库快照的方式回滚消费状态；那会重新授权已发订单。旧程序不兼容新 schema 时禁止直接降级发单。

POSIX 账户锁和 SQLite 事务只协调同一主机、同一账本的本工具进程。它们不控制人工 TWS、其他机器或第三方客户端，也不提供券商 exactly-once 语义。

## 交割证据与展期建议

`multiplier=100/200/500` 只代表计量乘数，不足以证实交割物是纯股票。相同 underlying conId 也不等于所有期权具有相同交割篮子。调整合约可能含现金或其他资产；不得由交易类别名称自动猜测。

展期引擎与 CLI 证据加载器要求旧仓及每个候选分别具备**该期权 conId**的交割确认。仅确认 underlying、仅确认一个同标的标准合约，均不能授权其他合约。所有执行入口已统一接通最新权威账本与执行协议，但仍严格遵守 offline/dry-run 边界。

`roll-plan --delivery-evidence <文件>` 使用独立 `thetamill.deliverables.v1` 文档；每条记录的 `instrument` 必须包含 `con_id`、`underlying_id`、`symbol`、`currency`、`sec_type`、`exchange`、`multiplier`、`right`、`strike`、`expiry`、`trading_class`，且逐字段匹配本次实际合格合约。记录另需 `stock_only: true`、非空 `source`、带 UTC 偏移的 `verified_at` 与 `expires_at`。数值可以使用精确十进制字符串，乘数不得统一填 100。证据必须来自真实交割条款核实，不是填一个布尔值就能证明；工具不提供虚构证据生成器。过期、未来或矛盾记录拒绝；缺少某 conId 的记录不授权该合约。

例如，旧仓和候选的 conId 不同时必须各有一条记录，即使二者标的和乘数相同。建议命令不会创建或修复提交账本：缺失、空文件、损坏或无法只读验证的账本均使新仓建议被阻断，不能通过新建空文件恢复。

新增 `roll-plan` 接口只生成建议，不执行买回或新开仓。显式 `--candidate-con-id` 可重复传入，不暗中限制候选数量，也不在候选全部不通过时放宽条件。新仓风控仍以原持仓快照计算，不能假设旧仓已平而释放担保。

建议分别保存旧/新合约乘数：净收支估算为 `新仓 bid × 新乘数 × 张数 − 旧仓 ask × 旧乘数 × 张数`。手续费未知另行标记；价格缺失时净额为未知。相同张数不表示相同交割义务。独立 schema `thetamill.roll.v1` 带 `recommendation_only=true` / `executable=false`，`run` 明确拒绝此类文件。

## 撤单与对账范围

撤单不仅要求账户和 orderId 匹配，还要求订单属于当前 API clientId。不同客户端可能使用相同 orderId；其他客户端的订单须回原客户端或 TWS 核对处理，本工具不通过 ID 猜测绑定。

`reconcile` 只查询券商并写入本地观察记录，不重发、不撤单、不自动释放预留。匹配以 orderRef / permId 等稳定身份为依据；标识矛盾、未知账户范围或多个匹配均停止。仅知道 orderId 不能证明目标属于该 intent。

报告必须合并券商快照和本地未交接预留；本地历史缺失时不展示可用预算数值，也不称完整。存在未决预留时，即使券商查询成功，也明确提示提交状态未解决。

## 验收与授权

离线测试、真实 ib_async 对象离线测试、Gateway 只读、纸账户提交/撤单、真实成交是不同证据等级。本轮 A 冷验证未进行新的账户操作。后续 Gateway 连接和任何纸账户委托/撤单仍须单独授权，不以工程 commit/push/PR 授权替代。
